Démonstration : message ANIBALAMIOTX

ANIBALAMIOTX est d'abord chiffré avec AES-256-GCM (clé stéganographique de 256 bits), puis le texte chiffré est dissimulé dans une grille 60×60 de nombres aléatoires, aux positions désignées par la taille de bloc (Clé B), l'orientation (Clé C) et la forme du Référent 256 (Clé 2) — le reste est du bruit indiscernable. La confidentialité vient du chiffrement, pas de la géométrie.

Référent 256 — Table des formes de la croix ansée

256 configurations géométriques distinctes issues des rotations (0°/90°/180°/270°) de la croix ansée d'ordre 6. Survolez une cellule pour voir ses positions. ×2 couleurs = 512 formes utilisables.

Référent 360 — Calques Jacquard

360 formes issues du métier Jacquard à 360 calques. Structure : 15 harmonies × 24 cartes. Chaque calque sélectionne 8 positions de lecture dans un bloc 12×12. (— formes extraites des fichiers SVG sources.)

Stéganographie géométrique — chiffrer puis dissimuler

Ce système est une application cryptographique des constructions arithmogéométriques développées dans La Livrée d'Hermès (Anibal Edelberto Amiot, 2026). Soumis à l'IACR Cryptology ePrint Archive en septembre 2026. Architecture revue suite à un audit cryptologique externe (2026-09-10).

Principe : le message est d'abord chiffré (AES-256-GCM), puis le texte chiffré est dissimulé dans une grille de nombres aléatoires. La confidentialité vient du chiffrement, la géométrie ne fait que cacher où se trouve le texte chiffré. Sans les clés, la grille est statistiquement indiscernable du bruit aléatoire.

Clé stéganographique — chiffrement : clé AES-256-GCM de 256 bits, générée aléatoirement par message. Chiffre le message avant toute dissimulation ; authentifie le déchiffrement (une clé ou des données incorrectes sont détectées, pas silencieusement corrompues).

Clé B — grammaire des blocs : taille de cellule par bloc — 6×6, 12×12, 18×18 ou 30×30.

Clé C — orientations : l'une des 8 transformations diédrales (D4 : rotations et miroirs) appliquée à chaque sous-bloc 6×6.

Clé 2 — formes et couleurs : sélection d'une forme et d'une couleur (bleu/orange) dans le Référent 256, par bloc.

Ancienne Clé A retirée : l'audit a constaté que le mélange secret du référent (Clé A) était entièrement redondant avec la Clé 2 — 0 bit de sécurité apporté malgré un espace de clés apparent de 2^1684. Le Référent 256 est maintenant utilisé directement.

Espace de clés (honnête) : confidentialité = 256 bits (AES-256-GCM) ; dissimulation géométrique = Clé B + Clé C + Clé 2 (jusqu'à 2^2300 bits pour une grille 60×60 en blocs 12×12). Une clé de dissimulation incorrecte échoue désormais à l'authentification AES-GCM — une erreur explicite, plus une fausse lecture plausible comme dans les versions antérieures.
Kerckhoffs : le système respecte le principe de Kerckhoffs (1883) — l'algorithme est entièrement public, le secret repose uniquement sur les clés et, optionnellement, sur des référents personnalisés.

Brevet antécédent : FR2865054 (2004) — composition automatisée d'un motif symbolique à partir d'une relation mathématique.

Chiffrement hybride — géométrique + AES-256-GCM

Architecture à deux couches, suite à un audit cryptologique externe : une couche géométrique (SPN Ref256+Ref360, S-box GF(2⁸), 4 tours) dérive une clé de session unique par secteur — diversification de clé, pas le chiffrement lui-même — puis AES-256-GCM chiffre et authentifie chaque secteur individuellement, avec une authentification HMAC-SHA256 globale par-dessus. Une passphrase incorrecte ou un fichier altéré sont détectés, jamais rendus en bruit silencieux. Distinct de l'outil de stéganographie ci-dessus. Entièrement côté client : la passphrase et les fichiers ne quittent jamais le navigateur.

Statistiques de sécurité

Couche géométrique (diversification de clé) : SPN Ref256+Ref360 — S-box GF(2⁸) (max_DDT ≤ 4 prouvé, Nyberg 1994), permutation Ref256 (12 288 configurations), MixBlock, permutation Ref360 (342 configurations), 4 tours — dérive une clé de session de 256 bits par secteur, non revendiquée comme chiffrement autonome
Couche standard (confidentialité + intégrité) : AES-256-GCM par secteur, tag d'authentification de 128 bits — la référence Python utilise XChaCha20-Poly1305 (absent de l'API Web Crypto des navigateurs) ; AES-256-GCM lui est substitué ici, même classe de garantie via l'implémentation native et auditée du navigateur
Dérivation de clé : PBKDF2-SHA256, 300 000 itérations — une fois passphrase → clé maître (sel de 128 bits géré par la page), une seconde fois clé maître → clé géométrique (sel de 256 bits propre à chaque fichier)
Nonce : 192 bits (aléatoire par fichier), un nonce distinct par secteur dérivé via HKDF-SHA256
Intégrité : tag AES-GCM par secteur + HMAC-SHA256 global (256 bits) — détecte toute altération ou passphrase incorrecte, jamais rendue en bruit silencieux
